WHAT IS THE DIFFERNCE BETWIXT AN ENCLOSURE AND A DOCK

Mar 12
Great question. This is Film School material.

An ENCLOSURE is a permanent home for a drive. You put a bare drive inside it, screw it in (or snap it in), close it up, and now it looks and acts like an external hard drive. It has its own case, its own USB cable, maybe its own power supply. TETHER is a drive inside an enclosure right now — that's what's dying. Not the drive. The enclosure's USB bridge board.

A DOCK is a parking spot. You slide a bare drive in from the top, use it, and pull it back out when you're done. No screws. No closing anything up. The drive sits there naked with its guts exposed, plugged into SATA contacts at the bottom of the slot. Like a toaster — you drop bread in, you pull bread out.

So the difference is commitment level:

Enclosure = marriage. One drive, one case, sealed up, lives together forever. You'd buy one enclosure per drive. That's what all your external drives are right now — TETHER, HEATHER, SPACESHIPBU. Each one is a drive married to an enclosure.

Dock = dating. Any drive can come and go. You have ONE dock and MANY bare drives. Pull one out, slide another in. The Sabrent EC-DFLT is a single-slot dock. The 5-bay DS-SC5B is a dock with five parking spots.

For a filmmaker with 25 years of drives accumulating? A dock is the move. You stop buying enclosures forever. You just buy bare drives — which are cheaper because you're not paying for the case, the USB board, the power supply, the packaging. You're buying the raw platter and motor. Then you park them in the dock when you need them.

That's why TETHER's enclosure dying doesn't mean TETHER is dead. The drive is fine. The marriage failed. We just need to give it a new place to park.

Now, your question about static vs complex sites and carousels. Let me be clear:

A static site CAN absolutely do a carousel. Your ZOOZBeat page in that screenshot — that carousel with the phones fanning out — that's just HTML, CSS, and JavaScript. No server needed. Static sites run JavaScript just fine. What makes a site "static" is that it doesn't need a backend database generating pages on the fly. All the code ships to the browser and runs there.

Here's the real difference:

Static site — HTML + CSS + JS files. Can do carousels, animations, transitions, scroll effects, video embeds, image galleries, parallax, everything visual. It just can't do things like user login, form submissions that save to a database, or dynamic content that changes based on who's viewing. Perfect for a portfolio, a booking agency landing page, an artist showcase.

Complex site — Needs a server. WordPress, a Cloudflare Worker with D1, etc. For things like: user accounts, a booking form that saves to a database, a CMS where Andre can edit his own content, an event calendar that auto-updates.

For Andre's 10 designs — static is the right call. Every one of those 10 designs should be a single HTML file (or a set of HTML files for the multi-page version). His text, his image links from the GoZoek site, arranged into 10 different visual experiences. We deploy them on dia-duit.com as static pages.
