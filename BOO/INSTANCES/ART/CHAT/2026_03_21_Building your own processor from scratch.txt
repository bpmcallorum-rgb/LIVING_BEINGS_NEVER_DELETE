Great questions, Brian — and honestly, these connect naturally to your zoetrope processor thinking. Let me walk through them.

The simplest processor
The simplest processor is a 1-bit ALU — it takes two single-bit inputs and performs one operation (like AND, OR, or ADD). You can build one from about 5-7 logic gates. That's it. That's a "processor."

The next step up is something like the 4-bit TD4 CPU — a Japanese hobbyist design that uses about 10 ICs (off-the-shelf chips on a breadboard). It can run simple programs. Many people build this as a first homemade CPU.

Have individuals built processors?
Yes, absolutely. A few notable ones:

Ben Eater built an 8-bit breadboard computer from scratch and documented the entire thing on YouTube — it's become the gold standard tutorial. Steve Chamberlin built "Big Mess o' Wires" (BMOW), a fully custom 8-bit CPU from individual transistors and logic chips. Sam Zeloof actually fabricated his own silicon chips in his garage — photolithography, doping, the whole process — and made working transistors and simple ICs. He's probably the closest anyone has come to a true home-fab processor.

And you're right about the warehouse era — ENIAC filled a 30×50 foot room and used 18,000 vacuum tubes to do roughly what a single modern transistor cluster handles.

Baby steps to building your own
The path typically goes: learn logic gates (AND/OR/NOT/XOR) → build a 1-bit adder → chain them into a 4-bit or 8-bit adder → add a clock, registers, and instruction decoding → now you have a CPU. You can do all of this on breadboards with 74-series logic chips from any electronics supplier. Total cost is maybe $50-100.

An even easier entry point: an FPGA board (like a Lattice iCE40, around $25-50), where you describe your processor in a hardware description language (Verilog or VHDL) and the FPGA physically reconfigures itself to become your design.

Do chip makers invent the system software simultaneously?
This is where it gets interesting. The answer is: partially yes, but mostly no.

The chip maker (say Intel or ARM) defines the instruction set architecture (ISA) — the contract between hardware and software. It's essentially the list of commands the chip understands. They also write the initial firmware, reference BIOS/UEFI implementations, and basic toolchains (compilers, assemblers).

But the operating system? That's almost always separate. Intel doesn't write Windows or Linux. They publish the ISA specification — a massive document (Intel's is over 5,000 pages) — and software companies build to that spec.

How can Company B write software for Company A's chip?
Because of that published ISA spec. It's a public contract. ARM publishes theirs, Intel publishes theirs, RISC-V is fully open. The spec tells you: here are the registers, here are the instructions, here's how memory addressing works, here's how interrupts fire. If you follow the spec, your software will run on the chip. You don't need to know how the chip implements those instructions internally — just what the interface is.

This is exactly the same principle as an API in web development. The chip is the server, the ISA is the API, the OS is the client.

Why doesn't Intel write all the system software?
A few reasons. First, antitrust — if Intel made the chips AND the only OS that ran on them, regulators would intervene (this nearly happened with Microsoft just for bundling a browser). Second, it's not their competency — processor design and OS design are fundamentally different disciplines. Third, the market benefits from competition — Linux, Windows, FreeBSD, and macOS all run on Intel chips, and that ecosystem diversity is what makes x86 dominant. If Intel locked it down, everyone would just move to ARM or RISC-V.

And fourth — Intel actually tried making their own mobile OS (Tizen, MeeGo). It failed. Turns out knowing your hardware best doesn't mean you know what users want from software.

The separation of hardware and software through a published ISA is one of the most important abstractions in computing. It's what lets the whole ecosystem work.
