## Brian — what "every hour" actually requires
This Claude session can't keep itself running. When the task ends, the container goes away and nothing loops. To get a real hourly heartbeat, one of these has to run on a schedule outside the session:

1. **GitHub Action on a cron schedule** (lives in this repo, no Mac needed):
   `.github/workflows/hourly-heartbeat.yml` with `on: schedule: - cron: '0 * * * *'` that opens a Claude Code job to read the latest index, write the next one, and commit/push. This is the simplest path — runs even when your Mac is off.
2. **Mac launchd / cron job** invoking `claude` against this repo every hour. Needs your Mac on and the agent CLI configured. Lives in `~/Library/LaunchAgents/`.
3. **Scheduled MCP / agent runner** (e.g. Patricia-side scheduler) firing a session per hour.

Until one of those is wired up, every "hourly" file is hand-written by an invoked session, and the timestamp in the filename is a pretty fiction — it says `12Z` because that's the convention Forge picked, not because the file was born at noon UTC.

If you want the GitHub Action path, say the word and the next session can open a PR with the workflow. It's small.
